## Текущие типы и текст

| Тип | Вид | Пример и маска |
| --- | --- | --- |
| type1 | Белый длинный | `A123BC77` / `A123BC177`, `LDDDLLRR/RRR` |
| type1a | Белый двухстрочный автомобильный | Тот же полный текст `A123BC77/177`, `LDDDLLRR/RRR` |
| type1b | Жёлтый длинный | `AB12377` / `AB123177`, `LLDDDRR/RRR` |
| other | Другой российский тип | Сохраняется фактически прочитанный текст; тип не подгоняется к целевым маскам |

Кириллические сходные буквы приводятся к латинским, регистр — к верхнему; идентичность номера в reviewer считается без пробелов/разделителей. Символы OCR автоматически не угадываются и не заменяются. Канонический парсер сам ничего не нормализует: принимает уже подготовленный ASCII-текст. Допустимые буквы: `ABEKMHOPCTYX`, цифры: `0–9`. `#` означает непрочитанную позицию; такие записи не дают полного OCR-номера для целевого минимума. Полностью неизвестный текст и известный регион `00/000` в актуальном профиле отвергаются. Проверки не подтверждают существование конкретной серии/регионального кода.

Желтоватый оттенок белой пластины из-за света/грязи не меняет её тип. Один цвет или количество символов могут служить предложением для очереди, но не подтверждают фактический тип и текст. Иностранные номера отмечаются в reviewer как «вне конкурса / иностранный».

Профили схемы:

- `russian_v1` — текущие маски для новых коллекций; у белых номеров разрешён любой двух-/трёхзначный регион, кроме полностью нулевого.
- `legacy_v2` — исторический контракт по умолчанию, включая старую белую маску для type1b и ограничение первого знака трёхзначного региона на `1/2/7/#`. Старые коллекции автоматически не мигрируют.

Для новых внутренних метаданных задавайте профиль явно. Профиль схемы не переключает recognition profile замороженной модели.

## Ручная проверка DATA-2B

Обычная проверка: [http://127.0.0.1:8765/single](http://127.0.0.1:8765/single). Подтверждение перспективных углов уже принятых карточек: [http://127.0.0.1:8765/corners](http://127.0.0.1:8765/corners). В `/corners` текст/тип сохраняются, а bbox не объявляется автоматически четырьмя углами номера. Подробности: [manual_corner_review.md](../docs/manual_corner_review.md).

| Тип | Verified images / target | Unique plates / target | Осталось images / unique |
| --- | ---: | ---: | ---: |
| type1a | 24 / 150 | 23 / 50 | 126 / 27 |
| type1b | 1 / 300 | 1 / 100 | 299 / 99 |

Это снимок состояния; актуальные counters показывает reviewer. Сначала P0/type1b:100 unique, затем300 images; далее P1/type1a:50 unique, затем150 images. После выполнения минимумов вся оставшаяся очередь не требует обязательного просмотра. Detector-only запись не входит в OCR minimum. Углы на момент снимка:0/34, приватность реальных кадров ещё требует проверки.

Для будущего DATA-3 сохраняются `plate_num`, `duplicate_group_id`, `source_family`, `original_image_group_id`, source/crop hashes и сведения о development exposure. Повторные размеры одного исходного кадра не увеличивают число реальных изображений. Известные связанные изображения и номера должны оставаться в одной группе. Подтверждение bbox и подтверждение quad — разные признаки.

## Три разных представления геометрии

| Место | bbox | quad |
| --- | --- | --- |
| Reviewer / verified index | JSON `[x1,y1,x2,y2]`, абсолютные пиксели | Четыре пары точек TL/TR/BR/BL, отдельное подтверждение человеком/источником |
| Внутренний `dataset.schema` | JSON `[x,y,width,height]`, абсолютные пиксели | JSON `[[TLx,TLy],[TRx,TRy],[BRx,BRy],[BLx,BLy]]`, float допустим |
| Экспорт организаторов | `x,y,width,height`, целые числа без скобок | Восемь целых чисел через запятую, без JSON-скобок |

Геометрия относится к сохранённому изображению. Начало bbox неотрицательное, площадь положительная, рамка и углы внутри изображения; bbox содержит quad. Quad строго выпуклый, по часовой стрелке при оси Y вниз, начинается с TL по минимуму `x+y`. Перевод между форматами выполняется явно; копирование массива bbox без изменения его смысла недопустимо.

## Внутренняя схема meta.csv

UTF-8, разделитель `;`, одна строка на номер; объекты одного кадра имеют одинаковое поле `image`. Десять основных колонок:

`image;plate_num;plate_type;bbox;quad;is_vehicle;is_synthetic;source;license;conditions`

Writer добавляет четыре внутренних поля: `annotation_kind`, `source_split`, `group_id`, `license_review`. Пути POSIX относительно корня коллекции, например `images/real/camera/a.jpg`; абсолютные пути, `..` и обратные слеши здесь недопустимы.

- `full`: bbox, тип и известный `is_vehicle`; optional quad во внутреннем legacy-контракте. Для сдаваемых реальных объектов дополнительно нужны подтверждённые углы и приватность.
- `ocr_crop`: текст относится к crop, bbox задаётся в его координатах; исходная рамка полного кадра и контекст автомобиля этим не подтверждаются.
- `detection_only`: настоящий bbox без OCR-текста, подтип/контекст могут быть неизвестны.
- `negative`: явно проверенный кадр без номеров, пустые текст/тип/геометрия и `is_vehicle=0`. Пропущенная разметка не является доказательством отрицательного кадра.

`is_vehicle` и `is_synthetic` сериализуются как `0/1`; неизвестный контекст допускается только у crop/detection-only. `conditions` — неповторяющиеся теги через `|`. `source_split` сохраняет исходный train/val/test; `group_id` содержит глобально уникальную идентичность в пространстве источника. `license_review` связывает сохранённые сведения об источнике с их evidence/hash. Исторический внутренний парсер принимает `CC-BY-4.0/CC0-1.0`; это ограничение конкретного legacy-контракта, а не описание прав всех staged-источников.

Для официального экспорта остаются ровно10 колонок, другая сериализация геометрии и фиксированный словарь условий. Внутренние14 колонок и JSON нельзя напрямую передавать оригинальному валидатору. Точная float-геометрия, группы и остальные условия сохраняются в provenance. Подробнее: [current_synthetic_review.md](../docs/current_synthetic_review.md).

`tools/export_organizer_synthetic.py` экспортирует только собственные синтетические сцены в новый каталог. Он не является готовым экспортёром verified real pool. Пустые кадры сохраняются auxiliary без выдуманных bbox/quad; непригодные исходные кадры сохраняются в quarantine с исходным текстом.

## Проверка без создания split

Из корня репозитория, для внутренней коллекции текущего формата:

```powershell
.venv/Scripts/python.exe -I tools/validate_local.py `
  --dataset PATH_TO_INTERNAL_COLLECTION `
  --report reports/current_collection_validation.json `
  --format-profile russian_v1 --no-splits
```

Валидатор проверяет перечисленные в meta.csv изображения, геометрию, маски, типы, provenance, противоречия и дубликаты. Он не доказывает визуальную правильность текста/типа/контекста и не заменяет оригинальный валидатор организаторов. Неуказанные в metadata файлы не дают дополнительной coverage. `valid=true` у пустого scaffold означает только согласованность структуры, `ready_for_e2e_evaluation=false` отражает отсутствие данных. Report размещается вне корня проверяемого датасета.

`tools/data3_preflight.py` отдельно проверяет реальные prerequisite, byte/group accounting и development exposure. Он не создаёт split. Пока real targets, ручные углы, privacy и независимые группы не обеспечены, окончательный DATA-3 не запускается.

Универсальный `tools/split_dataset.py` поддерживает `--format-profile russian_v1`; этот ключ передаётся парсеру и обеим проверкам. Профиль записывается в `splits/manifest.json`; проверка другим профилем даёт ошибку даже для текста, подходящего обоим. Manifest без поля профиля сохраняет историческое значение `legacy_v2`. По умолчанию legacy-поведение остаётся совместимым. Эта возможность инструмента не является разрешением создавать окончательный real split сейчас.
